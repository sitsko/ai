## Project Overview

Demo project showcasing **Quarkus + LangChain4J** integration for AI tool calling patterns. The single Maven module (`ai-tool-calling/`) demonstrates OpenAI function calling, guardrails, conversation memory, and observability.

## Commands

All commands run from `ai-tool-calling/` directory:

```bash
# Dev mode with live reload
./mvnw quarkus:dev

# Build JVM JAR
./mvnw package

# Build native image
./mvnw package -Pnative

# Run all tests
./mvnw test

# Run single test class
./mvnw test -Dtest=MyTestClass

# Run integration tests
./mvnw verify
```

HTTP request examples are in `ai-tool-calling/script/http/`.

## Setup

Create `ai-tool-calling/.env` with:
```
AI_APP_PORT=9080
AI_MODEL_PROVIDER=openai
OPEN_AI_TOKEN=<your-openai-token>
```

Requires Java 21. Supports switching to Ollama by setting `AI_MODEL_PROVIDER=ollama`.

## Architecture

### Package Structure

```
me.sitsko.ai/
├── vessel/     # Maritime vessel domain — tool calling + guardrails demo
└── customer/   # Customer generation domain — memory + structured output demo
```

### LangChain4J Patterns Used

- **`@RegisterAiService`** — Interface-based AI service that LangChain4J auto-implements
- **`@Tool`** on methods in `*Tool.java` classes — Functions the LLM can call (simulated external data)
- **`@SystemMessage` / `@UserMessage`** — Prompt templates defined directly on service methods
- **`@InputGuardrails` / `@OutputGuardrails`** — Validation before/after LLM calls (see `VesselInputGuardRail`, `VesselOutputGuardrail`)
- **`@MemoryId`** — Per-session conversation memory (used in `CustomerAiService` to maintain list state across requests)

### Key Design Decisions

- AI services are interfaces only; implementations are generated by LangChain4J at build time
- `*Tool.java` classes mock external service calls (vessel database) that the LLM can invoke
- `@RunOnVirtualThread` + `@Timeout(60)` (SmallRye Fault Tolerance) handle AI call latency
- Provider switching (OpenAI ↔ Ollama) via `AI_MODEL_PROVIDER` env var with conditional config in `application.properties`

### REST Endpoints

| Endpoint | Description |
|----------|-------------|
| `GET /api/vessels/{owner}/heavy` | Largest vessel by owner (tool calling) |
| `GET /api/vessels/{owner}/count` | Count vessels by owner (tool calling) |
| `GET /api/vessels/forecast?years=N` | AI-generated forecast (with timeout) |
| `GET /api/lists/{listId}` | Generate 3 random persons (memory demo) |
| `GET /api/lists/{listId}/customers/{id}` | Retrieve person from memory by ID |

### Observability

Dev mode starts a local LGTM stack (Loki, Grafana, Tempo, Mimir) via `quarkus-observability-devservices-lgtm`. Prometheus metrics exposed via Micrometer; endpoints annotated with `@Timed` / `@Counted`.

## Key Dependencies

- **Quarkus 3.23.4** with `quarkus-rest` + `quarkus-rest-jackson`
- **LangChain4J 1.1.0** (`quarkus-langchain4j-openai` / `quarkus-langchain4j-ollama`)
- **SmallRye Fault Tolerance** for `@Timeout` on AI calls
- **Lombok** for constructor injection
